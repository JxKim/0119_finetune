# 基于库的微调小测

## 微调使用的库
1. trl, peft, bitsandbytes, accelerate, deepspeed, unsloth分别解决的是什么问题？
<details>
<summary>参考答案</summary>

- TRL：主要用于大模型微调和对齐训练，常见能力包括 SFT、DPO、PPO 等，提供 `SFTTrainer`、`DPOTrainer` 等工具。
- PEFT：参数高效微调库，用来做 LoRA、QLoRA、Prefix Tuning 等，只训练少量新增参数，降低训练成本。
- bitsandbytes：提供量化能力，可将量化后的模型用作推理或者训练。
- accelerate：简化多 GPU分布式训练的过程。
- deepspeed：用于大规模训练优化，是ZeRO的具体实现框架。
- unsloth：偏向高效微调，对微调的各个环节都打补丁，加速训练过程，减少训练显存占用。

</details>


## 微调的超参数调整


1. 全参微调学习率一般设置范围多少？为什么？

<details>
<summary>参考答案</summary>

全参微调的学习率通常比较小，常见范围大约是 `1e-5` 到 `5e-5`。

原因是全参微调会更新模型的全部参数，参数量很大。如果学习率过高，容易破坏预训练模型已经学到的知识，导致训练不稳定、灾难性遗忘或者效果退化。

所以全参微调一般更保守：小学习率、较稳定的 warmup、较谨慎的训练轮数，并且需要密切观察验证集表现。

</details>

2. LoRA微调学习率一般设置范围多少？为什么？

<details>
<summary>参考答案</summary>

LoRA 微调的学习率通常可以比全参微调更高，常见范围大约是 `1e-4` 到 `5e-4`。

原因是 LoRA 不直接更新基座模型的大量原始参数，而是训练额外插入的低秩矩阵。可训练参数更少，对原模型的破坏更小，因此可以使用相对更大的学习率。

</details>

3. 微调可以怎么进行验证评估？  

<details>
<summary>参考答案</summary>

微调评估通常需要同时看自动指标和人工效果，不能只看 training loss。

常见做法：

- 准备独立的验证集 / 测试集，不能和训练集混在一起。
- 看验证集上面的损失，来判断模型的泛化能力。
- 微调后，让模型在特定的任务prompt下，自回归生成，使用更加强大的LLM作为裁判，来判断结果好坏。


</details>

4. 全参微调，如果发现效果不好，可以调整的超参数有哪些？按照优先级进行排序，最应该调整什么？

<details>
<summary>参考答案</summary>

最应该关心：
数据质量和任务格式：数据是否有噪声、标签是否一致、输入输出格式是否清楚、训练数据是否覆盖真实场景。
如果数据没问题，再来调整超参数：
1. 调整学习率：全参微调最敏感的参数之一。
2. 调整训练轮数 / 总步数：训练不足会欠拟合，训练太久会过拟合或遗忘。
   
其他影响不大的参数：
1. 有效batch_size: 32或者48，
2. warmup_ratio: 0.1
3. weight_decay:权重衰减系数，一般来讲0.01


</details>

5. LoRA微调过程中，如果发现在实际任务上面评估表现不好，可以调整的超参数有哪些，按照优先级进行排序，最应该调整什么？

<details>
<summary>参考答案</summary>

最应该关心：
数据质量和任务格式：数据是否有噪声、标签是否一致、输入输出格式是否清楚、训练数据是否覆盖真实场景。
如果数据没问题，再来调整超参数：

1. 调整学习率：LoRA 常用较高学习率，但过高会导致输出不稳定，过低可能学不动。
2. 调整训练轮数 / 总步数：判断是欠拟合还是过拟合。
3. 调整 `target_modules`：如果只插了很少模块，模型可调整空间可能不够；可以从 `q_proj/v_proj` 扩展到更多 attention 或 MLP 模块。
4. 调整 LoRA rank `r`：`r` 越大，表达能力越强，但显存和训练成本更高。

其他影响不大的参数：
1. 有效batch_size: 32或者48
2. warmup_ratio: 0.1
3. weight_decay:权重衰减系数，一般来讲0.01
4. lora_alpha: 一般设置成r，只有在r的增大已经没有用了，可以尝试再将lora_alpha调整成2r，改变LoRA的强度。


</details>

6. 显存不足时，应该优先减小 LoRA 的秩和插入模块数量，还是使用 QLoRA？请说明它们节省显存的原理、对效果的影响，以及实际选择依据。

<details>
<summary>参考答案</summary>

减小 LoRA 的秩 `r`、减少 LoRA 插入模块数量，和使用 QLoRA，省显存的方向不一样。

减小 LoRA 的秩和插入位置，主要减少的是 LoRA adapter 的可训练参数、梯度和优化器状态。这样会降低训练开销，但基座模型本身仍然需要按原精度加载，所以如果显存大头是基座模型权重，这种方式节省有限。

如果想要训练的模型本身占据的显存就很大、普通 LoRA 放不下，或者想在单卡上训练更大模型时，就可以考虑使用QLoRA来进行训练。


</details>
    
7.  综合说下，避免模型过拟合的手段，有哪些？

<details>
<summary>参考答案</summary>

避免过拟合可以从数据、训练过程和模型参数三个层面入手：

最应该考虑的点：
- 提高数据质量，减少重复、错误、噪声样本。
- 增加数据多样性。
- 控制训练轮数，避免训练太久。
- 控制学习率。
其他手段：

- 使用 weight decay 等正则化手段。
- 保留一组真实业务样例做人工评测，检查模型是否只是记住训练格式，而没有真正提升任务能力。

</details>

1.  什么是梯度裁剪？

<details>
<summary>参考答案</summary>

梯度裁剪是指在反向传播后，如果梯度的范数超过某个阈值，就把梯度缩放到阈值范围内，避免一次参数更新过大。

它主要用于提升训练稳定性，防止梯度爆炸，尤其是在大模型训练、长序列训练或者学习率偏高时比较有用。

</details>
